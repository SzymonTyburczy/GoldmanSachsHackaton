How it works

Rules decide. AI assists.

Deterministic checks run first. The AI detector can only add a denial, never grant access.

  1. IdentityRole and client from the server, not the agent
  2. AccessChecked before any document is read
  3. PrivacyFields removed, PII and secrets masked
  4. AI riskInjection and exfiltration scored
  5. BudgetCost reserved atomically
  6. ModelRuns only if every check passes
  7. AuditDecision and actual effect recorded
PromptSent to model Masked locally · 3

Local Presidio plus a dedicated secret rule. Masking happens before any provider call, including token counting. If the engine is down, nothing leaves.

Threats it stops

Four ways AI goes wrong.

CLIENT_FORBIDDEN

Another client's file?

Blocked before it's read.

Identity, role and client scope come from verified server state. The document adapter is never called.

SEMANTIC_RISK

A hidden instruction?

Caught. The summary never runs.

TypeSafe Jev scores instruction override and data exfiltration. Above the threshold, or if the detector fails, generation stops.

BUDGET_EXCEEDED

A runaway loop?

Stopped at the budget.

Atomic reservations per task, user and globally. In our test, 20 parallel requests with budget for 5: exactly 5 run.

ARTIFACT_BLOCKED

A poisoned model file?

Rejected by the threat feed.

Trusted SHA-256 manifest, a hash threat feed and strict JSON. Altered or pickle-like files are never deserialized.

    "global_limit_nusd": 500000000
  }
